浏览器访问 http://127.0.0.1:8096；局域网访问使用启动日志显示的主机地址。健康检查：curl http://127.0.0.1:8096/api/health。

摄像头 3 配网与视频流

  1. 手机或电脑临时连接摄像头 AP，按说明书进入 BTACAM 的 AP 热点配置。
  2. 把摄像头加入与 IPC 相同的工厂 Wi-Fi；路由器按 MAC c4:3c:b0:be:40:e8 建立 DHCP 静态租约 192.168.1.135。
  3. 在网页“现场监控 → 网络摄像头 3”填写厂家 App 提供的完整 RTSP 地址，先测试再保存。
  4. 也可命令行验证：./.venv/bin/python scripts/probe_network_camera.py 'rtsp://用户名:密码@192.168.1.135:554/实际路径'。

平台支持有限候选路径自动探测，但不会猜测或暴力破解账号。根地址返回 400 时，必须回到 BTACAM App 的播放/分享页复制完整地址。

3. Windows RTX 工控机

  1. 安装 Python 3.12 x64、NVIDIA 驱动和与现场 CUDA 匹配的 PyTorch。
  2. 解压工程，执行 py -3.12 -m venv .venv 和 .venv\Scripts\pip install -r requirements.txt。
  3. 使用 启动SOP平台_Windows.bat 启动服务；浏览器打开 http://127.0.0.1:8096。
  4. 在“训练与部署”页先登记训练/灰度单；生产替换必须由工艺和质量双人确认。

4. CPU/低功耗边缘设备

使用 ONNX Runtime 加载 models/yolo26n_两视频小目标蒸馏_待人工验收.onnx。建议 640 输入、5 FPS 以下、单路摄像头；低功耗设备只做辅助告警，不能单独作为最终放行门。

6. MES 联调

生产接口至少需要：工单下发、结果回传、业务 ACK、错误码、幂等键、离线补传和审计查询。平台本地 /api/mes/test 只验证事件落盘和模拟 ACK，不会连接生产 MES。正式联调前由 IT/MES 提供测试 URL、认证、字段字典和回执样例。

7. 故障排查与回滚

  • 相机网络不可达：检查工厂 Wi-Fi、DHCP 租约、路由、554 端口；AP 配网地址仅用于临时配置。
  • RTSP 400：路径或认证不正确，从 BTACAM App 复制完整播放地址。
  • 网页无画面：检查同一相机是否被其他进程占用，Linux 使用 fuser -v /dev/video0。
  • 模型异常：停止服务，恢复上一版模型/配置/依赖目录，保留事件日志后再分析。
  • MES 超时：保持 HOLD，本地队列按事件顺序重试，禁止人工删日志后放行。
交付原则：视觉建议可以解释，确定性门禁必须可审计；任何缺少工具回执或 MES ACK 的结果保持 HOLD。
