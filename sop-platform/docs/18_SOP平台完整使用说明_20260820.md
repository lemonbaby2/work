# 宁波零部件 SOP 行为分析与 AI 视觉平台完整使用说明

版本：soplzp0820 / 2026-08-20

## 1. 系统用途与边界

本系统将工位相机、SOP 阶段、目标检测、动作候选、语音提醒、CVAT 人工标注、模型训练、质量处置和 MES 留痕组织在同一平台中。系统的自动框、动作和 ROI 默认都是候选，未经人工确认不得作为量产真值，也不得自动输出合格结论。

平台主地址为 `http://192.168.1.129:8096`，CVAT 地址为 `http://192.168.1.129:8081`。同一局域网的 2.4 GHz 或 5 GHz 终端均可访问；两个频段必须处于互通的同一 VLAN，且交换机或路由器未启用 AP 隔离。

## 2. 登录角色与权限

平台首次运行会生成开发者、管理者、普通员工三个账号，初始凭据只保存在服务器 `runtime/initial_credentials.txt`，文件权限为 600，不进入 Git 和交付文档。

- 开发者：拥有全部页面，可切换底层产线模型、同步 DGX 模型、管理设备和系统配置。
- 管理者：可查看总览、现场监控、证据处置、SOP 编排、CVAT、训练、MES 和质量报告；不能修改底层系统配置。
- 普通员工：可查看总览和现场监控，可在标注页画框、插值、保存进度和进入 CVAT；不能训练、切换模型或操作 MES。

登录成功后右上角显示姓名和角色。离开工位时点击“退出”。后端会同时校验角色，隐藏按钮并不代表唯一的安全措施。

## 3. 总览页

总览用于快速回答四个问题：设备是否在线、视觉证据是否齐全、当前为什么 HOLD、接下来应该由谁处理。

页面顶部显示平台、DGX、CVAT 和 MES 状态。KPI 显示视频任务、视觉证据帧、SOP 阶段和质量放行状态。真实工位画面中的框是候选框示意，点击“查看证据”进入现场监控。近 7 日“证据完备度”只表示目标、动作、ROI 和审核字段是否齐全，不等于模型精度。

## 4. 摄像头与现场监控

进入“现场监控”，先点击“刷新设备”，再点击“启动全部”。系统会重新扫描 `/dev/v4l/by-id`，使用稳定设备路径绑定 Jieli、Orbbec、icSpring 或后续热插拔的 UVC 相机。每路流采用容量为 1 的最新帧邮箱，旧帧直接丢弃，避免延迟越积越大。

影石相机只有在 `lsusb` 和 UVC 设备树中被枚举后才能被平台调用。若页面显示未检测到影石，请依次检查数据线是否支持数据、相机供电、UVC/Webcam 模式、USB 扩展坞带宽，并重新插拔后点击“刷新设备”。不要重置整个 USB Hub，以免同时中断键盘、鼠标和其他相机。

USB 串口只能承载控制命令和设备身份，不能替代视频链路。网络相机应将 RTSP/HTTP 地址写入 `config/network_cameras.json`。

## 5. S01–S04 互动复盘

点击阶段条目会跳转到对应视频时间并显示该阶段 ROI。

- S01 取料候选：确认手部进入料区并拿取物料。
- S02 元器件对位候选：确认元器件、PCB 和目标位置关系。
- S03 插装/按压候选：确认手、工具和元器件的连续操作。
- S04 完成复检候选：确认成品区域、缺失项和 NG 证据。

阶段边界、遮挡、方向改变和 NG 位置应增加关键帧。固定目标可每 15–30 帧确认一次，手、工具和运动目标建议每 3–5 帧确认一次。

## 6. CVAT 全量项目

共享项目名称为“宁波SOP全量视频标注_20260820”，项目位于 `lan-team` 组织，原有 `annotator1` 至 `annotator5` 均可查看。CVAT 采用一段视频一个 Task，避免单个任务过大导致浏览器或数据库崩溃。

全量脚本扫描 `/home/xjai/Desktop/sop xjai/视频数据`，跳过空文件，使用 ffprobe 排除损坏视频；大于 2 GiB、MKV、MOV 或非 H.264 文件先转成 1280 像素宽、15 FPS、H.264 代理视频。原片不删除，状态清单记录原片路径、大小、代理文件、Task ID 和失败原因。脚本通过 JSONL 清单断点续传，重复执行不会重复提交成功任务。

标注员在 CVAT 中选择项目和 Task，播放整段视频，在关键帧画框后使用 Track/Interpolation 传播。完成后先保存，再将任务状态交给质量人员审核。PCB、手、电烙铁、夹具、镊子、刷子、电容、电感、螺钉和工位 ROI 必须分开标注。

## 7. 网页标注与保存

在“05 CVAT 标注”选择视频和区域，播放到关键帧后拖动鼠标画框，填写标签和轨迹编号，点击“保存这个框”。到下一个关键帧调整框后点击“插值到当前关键帧”，中间生成的框仍为待复核候选。

完成一批后点击“保存本次进度”。系统会将框坐标写入 SQLite WAL 数据库，同时创建一致性备份，并在工具栏下方显示保存轮次、区域、框数量和时间。页面每 60 秒提醒一次保存；未保存离开页面时浏览器会警告。

## 8. 真实训练与验证

训练页按以下顺序操作：

1. 选择基础模型和已加载的本地 YOLO 数据集。
2. 查看图片数、标签文件数和真值状态。
3. 正式训练选择“仅人工确认真值”；待复核数据会被后端拒绝。
4. 若只是扩充教师模型候选，可选择“候选预训练”，但其指标不得作为量产精度。
5. 设置 Epochs、Batch Size、输入尺寸、Workers、Patience、随机种子、设备和结果目录。
6. 选择 Jetson、CUDA Server 或 ONNX Server 部署目标。
7. 点击“开始真实训练与验证”，等待页面显示实际日志、进度和预计时间。

“高级参数”可配置优化器、初始学习率、权重衰减、Mosaic 关闭轮次、冻结层数、RAM/磁盘缓存和 AMP 混合精度。不了解参数含义时应保留推荐值，并由开发者根据显存和验证曲线调整。

当前默认 5 轮、Batch 4、输入尺寸 960，适用于 PCB 小目标试验。显存不足时先减小 Batch；小目标漏检明显时可提高输入尺寸，但训练和推理都会变慢。

训练进程会真实执行 train 和 val，输出 `best.pt`、`best.onnx`、`deployment_manifest.json` 和部署 ZIP。Precision、Recall、mAP50 和 mAP50-95 只有在人工真值、冻结验证集以及按完整视频或产品 SN 划分时才具备生产含义。

## 9. Jetson 与服务器部署

下载训练页生成的部署 ZIP。Jetson TensorRT Engine 与 JetPack、CUDA、TensorRT 和具体 GPU 架构绑定，不能直接从 DGX 复制 Engine。应在目标 Jetson 上从 `best.pt` 或 `best.onnx` 构建 Engine，再使用目标相机验证类别映射、前处理、P95 延迟和连续运行稳定性。

CUDA 服务器可以使用 `best.pt` 或 ONNX/TensorRT；通用服务使用 ONNX Runtime。任何部署都应先单工位灰度，保留旧模型和一键回滚路径。

## 10. 数据库与备份

平台标注数据库使用 SQLite WAL、FULL synchronous 和 30 秒 busy timeout。每次任务级保存都会产生一致性备份。不得在服务运行时只复制主数据库文件而遗漏 WAL；优先使用平台备份或 SQLite backup API 生成的文件。

CVAT 使用独立 PostgreSQL/Redis/对象数据卷，并有存储水位保护。批量上传脚本在剩余空间低于 80 GiB 时自动暂停。禁止把 CVAT Token、平台初始密码或实时数据库提交到 GitHub。

## 11. 精度提升流程

优先使用 YOLOE/Grounding DINO 生成开放词汇候选；PCB 和物料 ROI 使用切片检测；手和工具使用 Detector + ByteTrack/OC-SORT；首帧人工确认后再用 SAM2 Video 或跟踪传播。低置信度、漏检、误检和类别混淆进入主动学习队列。

每一轮训练后使用固定测试集比较，不因结果不理想而改动测试集。NG、稀有类别、刷子、小电容、小电感、螺钉、焊点和工序边界必须人工复核。

## 12. 常见故障

- 登录后页面返回 403：当前角色没有该操作权限，请由管理者或开发者执行。
- 摄像头黑屏：刷新设备，检查是否被 ffplay 或其他进程独占，再查看采集错误。
- 三路画面延迟：降低显示宽度或 JPEG 质量，保持最新帧邮箱，不提高推理并发。
- CVAT Task 显示 size 0：视频仍在后台解码，等待 Request 状态完成后刷新。
- 正式训练被拒绝：数据仍是待人工复核候选，先从 CVAT 完成审核并冻结真值版本。
- CUDA OOM：减小 Batch，其次减小输入尺寸，再减少 Workers。
- Jetson Engine 不能加载：必须在目标 Jetson 和对应 JetPack 环境重新构建。

## 13. 审计要求

任何“合格”“优秀精度”“已完成标注”的结论都必须附人工审核人、冻结数据集版本、测试集拆分规则、模型哈希、验证报告和部署版本。自动候选数量不能替代人工真值数量。
